### A-03 · bloqueia · dentro-do-bloco · a "ordem global de locks" do §3.1-6 é falsa — o `FOR UPDATE` do V6 cria DOIS ciclos de deadlock novos
- **Evidência (`LO_open_forUpdate`):** X = menor id (criado antes), Y = maior id. A = close-do-plano trava X `FOR UPDATE`, segura 1,5 s, pede Y. B = `CycleCountService.open` REAL, 300 ms depois (`createSession` insere as entries na ordem de `listItems` = `created_at desc` = **[Y, X]**, `inventory-prisma.repository.ts:101`). Resultado: **A → `P2010 … Code: 40P01. Message: deadlock detected`**; B ok (`sessao entries=[Y,X]`). **Controle** (`LO_open_controleKeyShare`, A com `FOR KEY SHARE` — o lock que o close do head-base toma de fato via FK do INSERT): **sem deadlock**, A e B ok.
- **Evidência (`LO_abc_forUpdate`):** mesmo arranjo, consumo Y=50 > X=1; B = `InventoryService.recalculateAbc` REAL → `applyAbcClasses` numa tx única na ordem consumo DESC (`inventory.abc.ts:49-55`) = Y, X. Resultado: **A → `40P01 deadlock detected`**; B ok (`{"A":1,"B":0,"C":1}`). Controle `FOR KEY SHARE`: **sem deadlock**.
- **Motivo:** o plano afirma "`open` … sem segurar item nenhum antes → sem ciclo. Provado por A12/B6 (0 × 40P01)" (l.136-137) sem ter medido: o `createMany` segura `KEY SHARE` de Y enquanto espera X, e `applyAbcClasses` segura `NO KEY UPDATE` de Y enquanto espera X; o `FOR UPDATE` do V6 conflita com os dois (o próprio §3.1-3 e §3.1-5 dizem isso). Os ciclos só existem porque o V6 passa a travar itens `FOR UPDATE` — o controle mostra que o head-base não os tem. A12 e B6 (l.294, l.307) não exercitam `open` nem o recálculo ABC, e os critérios de verde deles são disjuntivos ("um recusa … ou ambos commitam"; "ajustes corretos ou 422/409 explicáveis") — não ficam vermelhos pelo defeito que dizem provar. Nas duas medições o Postgres escolheu o **fechamento** como vítima → `P2010` → 500 no `close`. Regra do próprio plano (§6): "Deadlock `40P01` nunca aceitável".

### A-06 · bloqueia · dentro-do-bloco · o V6 numa transação única sob o timeout default (5 s) torna o fechamento IMPOSSÍVEL acima de ~650 itens divergentes — e o plano proíbe subir o timeout sem ter medido o V6
