### R2-1 · `bloqueia` · `dentro-do-bloco` — o cursor `created_at|code` perde OS no Postgres: o `created_at` é `timestamptz(6)` (µs) e o cursor carrega o `Date` do JS (ms); o ramo de desempate `created_at = cursor` nunca casa
- **Evidência 1 (precisão da coluna e de quem a grava):** `awk '/^model WorkOrder \{/,/^\}/' prisma/schema.prisma | grep created_at` → `created_at DateTime @default(now()) @db.Timestamptz(6)`; migração `20260616000000_add_work_orders/migration.sql:29` → `"created_at" TIMESTAMPTZ(6) NOT NULL DEFAULT now()`; `sed -n 100,155p work-order-prisma.repository.ts` → o `create` **não** passa `created_at` (vale o `DEFAULT now()` do banco, em µs — a referência do Prisma diz de `now()`: "Implemented on the database-level" para bancos relacionais). O `mapWorkOrderRecord` devolve `Date` (`createdAt: record.created_at`, l.928): `node -e "new Date('2026-10-25T12:00:00.123456Z').toISOString()"` → `2026-10-25T12:00:00.123Z`.
- **Evidência 2 (o SQL que o Prisma gera para o cursor do §3):** `prisma-sql-probe.mjs`, caso E → `WHERE (tenant_id = $1 AND (created_at < $2 OR (created_at = $3 AND code < $4)))` · `args: ["t","2026-10-25T12:00:00.123Z","2026-10-25T12:00:00.123Z","OS-0100"]` — o parâmetro é o instante em **ms**.
- **Evidência 3 (execução em Postgres real, PGlite):** `cursor-us-probe.mjs` → `ordem real: OS-0003@…00.123456 | OS-0002@…00.123100 | OS-0001@…00.100000 | …` · `limit=1: trazidas=[OS-0003,OS-0001,OS-0005,OS-0004] paginas=5 FALTARAM=[OS-0002] (caminhada terminou "completa": nextCursor=null)`. A OS criada no mesmo milissegundo da OS de fronteira, com µs menor, **não é entregue** e a caminhada termina "completa".
- **Motivo:** o §4.2 confia na caminhada completa para **apagar** do aparelho o que não veio (sem trabalho pendente). Com a OS da fronteira pulada, uma OS que **continua sendo do técnico** some do celular — e de forma **determinística** enquanto o conjunto não mudar (a fronteira cai sempre no mesmo lugar). É a classe do CRIT-11 (`bloqueia` na r1), reaberta pelo próprio remédio. O empate exato também escapa: o ramo `created_at = $3` compara µs com ms e só casa quando a fração de µs é `000`. **Os critérios passam por construção:** CA-9/B14/B15 e B10 rodam no repositório de memória, cujos `Date` têm ms (`sortedWorkOrders`, `work-order.repository.ts:567-568`), e o §7 só manda ao job `backend-postgres` B1-B3 e B7 — nenhum teste de cursor toca a coluna `timestamptz(6)`. **Paginação (`limit=100`, teto 50 → "dados desatualizados"):** é o comportamento honesto (sem prova de fim, não purga; `nextCursor` ausente = incompleto). Com a E1 o teto vale sobre abertas e volta a ser borda. O problema não é o teto, é a prova de fim mentir no Postgres (R2-1).
